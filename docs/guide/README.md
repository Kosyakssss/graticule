# Graticule in plain words

This guide explains Graticule for someone who doesn't write code. It grows a little every time something lands that changes what you can see or do.

## What Graticule is

A toolkit for making desktop apps. You describe what your app knows, what can happen in it and how it should look; Graticule handles everything between that description and the pixels: the window, the mouse and keyboard, text, scrolling, drawing on the graphics card, accessibility, undo.

It's built on a grid, like graph paper. Every box, line and button in an app sits exactly on the squares. Inside a box, anything goes: a photo, a chart, a map, a waveform. The grid keeps every app tidy; the inside of the boxes is where each app is itself.

## The scoreboard

Think of a stadium scoreboard.

- **The facts**: home 2, away 1, 67th minute. Just information.
- **The commands**: "goal for home", "minute passes". The only things that can change the facts.
- **The view**: the rule for how the facts look on the board. Big yellow digits, the clock in the corner.

Nobody paints the board by hand. Someone presses "goal for home", the facts change, and the board redraws itself from the new facts. A Graticule app works the same way, and that one idea gives a lot for free:

- **Undo** is going back to older facts.
- **Rewind** in Scope is scrolling through the facts over time.
- **Specimen** can show any screen in any situation, because a situation is just a set of facts.
- **Sync** between your devices sends what each command actually changed ("added this item here"), not the command itself ("clear the finished ones"), because the same command can mean different things on two devices. So the lists on your laptop and your phone always end up the same, and nothing gets lost when both change at once.
- **Speed**: when one fact changes, only the part of the screen that shows it is redrawn.

## The tree

Between the view and the pixels sits a tree: a list of every box on screen, what kind of thing it is, where it is on the grid, and where in the code it came from. It's what the web calls the DOM, but rebuilt from the facts each time and much simpler, because the grid removes most of the measuring.

Everything reads that one tree: drawing, clicking, screen readers, Specimen, Scope, the taste checks, printing.

## From a click to the screen

Say you tick an item in a to-do list.

1. Graticule looks up which box is under the mouse in the last tree. Every square of the grid already knows its box, so this is instant.
2. The box knows its command: "mark ‘buy milk’ done". Graticule checks the command is still allowed, then runs it, and the facts change.
3. Ledger writes down exactly what changed (this item, done is now yes), which is what undo, saving and sync use later.
4. The view builds a fresh tree from the new facts. In a list of ten thousand items only the rows on screen are built.
5. Graticule compares the new tree with the last one, finds that one row changed, and redraws only that row.

Typing works the same way: each keystroke is a small command that changes the field's text, so it can be undone like anything else. When nothing happens, none of this runs.

A list of fifty million items behaves the same. Lists keep running counts (how many items are done), so questions like "is anything finished?" are instant. Work that really does have to touch every item, like clearing all the finished ones or exporting the whole list, runs in the background with its progress in the status line, and the app keeps responding while it runs.

## Commands are everywhere at once

Every command has a name and a label. From that single list Graticule makes the action bar, the help page, the palette, the menus, the right-click menus and the keys. Keys live in a separate file you can edit while the app runs. Press the first key of a sequence and the bar shows what can come next, like Helix.

The same list lets scripts and AI tools drive any Graticule app completely, which is why things like voice control don't need to be built in.

## The units

Graticule is made of named parts, each with a model code. Every one is two things: a piece that apps build in, and something of its own you can open or run. So every unit also shows Graticule working.

- **DK-01 Kernel.** Graticule itself: the grid, drawing, keys and mouse, the window. On its own: a new empty app.
- **LD-01 Ledger.** The app's memory. Every command is written down in order, along with exactly what it changed; from those come saving, undo, rewind, crash replays and syncing between your devices. On its own: a command that shows any app's history.
- **GA-01 Galley.** Text: huge files, many cursors, spelling, good typesetting, Helix-style keys. On its own: a text editor. Named for the tray typesetters set lines of type in.
- **PL-01 Plotter.** The canvas, modelled on tldraw: shapes, arrows that stay attached, snapping, endless boards, maps. On its own: a whiteboard. Named for the pen plotters that draw lines on paper.
- **SP-01 Specimen.** The catalog. Every component, live; every screen of every app in every state; the style editor; and the Changes page, where you see what looks different since you last approved it and say yes or no. This is where you review work without reading code.
- **SC-01 Scope.** The microscope over a running app: why it redrew, how long it took, where the code for any box is, and a rewind slider. It costs the app nothing measurable.
- **AS-01 Assay.** The inspector of quality. It checks any app against the rules every Graticule app must follow: never crashes, undo always works, everything on the grid, readable contrast, fast enough. On its own: a report for any app. Named for the test of what a metal is made of.
- **EN-01 Engraver.** Turns drawings (SVG files) into icons inside the app.
- **BD-01 Bindery.** Makes a real Mac app out of the code, installs and updates it, and reloads the app the moment code is saved while someone is working on it.

## The demo apps

Galley's editor and Plotter's whiteboard are already apps. Beside them, six small apps each push Graticule somewhere hard: Twin (files), Ticker (fast live data), Atlas (maps), Patchbay (wires and boxes, built on Plotter), Lightbox (photos and scans) and Four-track (recording music). They live next to Graticule, so any change to it shows in all of them at once.

## The order things are built in

The build plan, at the end of the spec, is one list from top to bottom, and anyone (a person or an AI) asked to build Graticule works down it item by item.

1. **A first slice through everything**: a tiny to-do app that runs in a real window with undo, saving and the palette. It isn't a demo app; it's the smallest thing that touches every layer, so design mistakes show up while they're cheap.
2. **The tools**: Specimen properly, Scope and Assay small, the development loop, icons.
3. **The components**: every one from HeroUI and Blueprint, built in batches, each with its page in Specimen. The owner then removes the ones Graticule doesn't keep.
4. **The units' engines**: Ledger in full with sync, Galley, Plotter.
5. **The demo apps**, each one using every component it touches.
6. **Linux, then Windows.**

## What runs today

`cargo run -p todo` opens the to-do app. It shows its page: the field, the list and the buttons, with the action bar along the bottom listing every command, and a status line that says what the thing under the pointer does and, when it can't, why. A button that can't run right now is drawn faint instead of hidden. Ticking an item, removing one, clearing the finished ones and scrolling a long list work with the mouse.

The keyboard works too. Tab moves between the field, the buttons and the list; the arrows move through the list, Shift with the arrows chooses several items, and Escape lets go. Typing into the field works the way it does everywhere else on the computer, copy and paste included, and Return adds the item. The to-do app's own keys are in `apps/todo/keymap.txt`, a plain file anyone can read and change: Delete or `d d` removes the chosen items, Space ticks one, and Ctrl-Shift-P (Cmd-Shift-P on a Mac) opens the palette. Those are the keys the app ships with; anyone using it can change them without rebuilding it. "Edit the keys" in the palette opens the user's own copy of the file in the system's text editor, and every change applies the moment the file is saved. A line the app can't read is named in the message line and the keys that worked stay in use; deleting the file brings back the keys the app shipped with. A number typed first applies a key to that many rows: `3 d d` removes the focused item and the two below it, as one step that one undo takes back, and `3` then the down arrow moves three rows. The bar at the bottom shows the number while it waits for the key, and Escape lets go of it. A keymap can also have modes, as text editors like Vim do: in normal mode letters run commands, in insert mode they type, and in select mode moving extends the choice. The bar at the bottom always shows the mode, and a pair like `d j` removes the focused item and the one below it. None of the demo apps uses modes yet; the keymap file decides. After the first key of a sequence, the bar at the bottom shows what can come next. The palette lists every command with its keys; typing narrows it, Return runs the highlighted one, and one that can't run says why. A command that needs something typed, like "Rename…", asks for it right there: the palette names what it wants (some text, a whole number, yes or no), and if what was typed doesn't fit, it says so and asks again. "Show the help" in the palette lists everything the app can do, with the keys for it and, for anything that can't be done right now, why; the arrows and Page Up and Down move through it and Escape closes it. "What's this?" turns the next click into a question: instead of pressing the button, it says what the button does, its keys and whether it can run now. "Show what was done" lists everything done in the window, newest first, with the time: each change, each undo and redo, each switch of the look. An app's settings come straight from its data: each one gets the right control by its kind (a switch, a set of options, a number with minus and plus, a field), each change can be undone on its own, and "Show only the changed settings" hides everything still as it was at first. A long page of settings can have a search field over it: typing a few letters of a setting's name leaves only the settings that have them. With several items chosen, "Remove 4 items" removes them all at once, skipping and naming any it can't. Ctrl-Z (Cmd-Z on a Mac) undoes and Ctrl-Shift-Z redoes: a typed word, an added item, a removal of four items at once, each as one step, and undoing puts the chosen items and the place in the field back as they were.

The app keeps what you did. Every change is saved as it happens, so closing the window loses nothing and a crash loses at most the change being written at that moment; the next launch opens with the same list, the same item chosen and the list scrolled where it was. Each app keeps its things in its own folder in the computer's place for app data (on Windows, `AppData\Roaming\Graticule\todo`). If something there can't be read, it is moved aside rather than deleted, and the app says so.

Clearing the finished items of a very long list doesn't freeze the window. The search happens in the background, the items go a few hundred at a time between frames, and the line above the bar counts them down ("“Clear finished”: 10000 of 33333"). Undo while it runs stops it and puts everything back; once it's done, it is one step like any other.

Export… asks where to save the list, the way every app on the computer does, and then writes it in the background as a Markdown checklist. The line above the bar says "Saving “To do.md”" while it works and the message line says where it went. Calling off the save panel does nothing at all.

`cargo run -p todo -- --specimen` opens Specimen over the to-do app instead: the same window, but showing the app's named states (empty, a few things, a very long list, long titles), each one live on its own copy, so you can click and type without touching your real list. The bar has a "Show …" command for each state. Export shows what it would have done instead of opening the save panel. Specimen's other places are in the bar too: Components, a live page of every piece Graticule draws with (the text, buttons, links, boxes, fields and lists). Each piece has its own page too: what it is for, how app code asks for it, its keys, what a screen reader says, the piece itself to try, and the piece with awkward content (nothing, very long text, right-to-left, Chinese, emoji, a huge number). The pages are written in `docs/components/`, so a change to the words shows in Specimen the next time it is built. Style shows every ink of the theme, light and dark, with its numbers and how well text in it reads on the background, and the sizes the grid and the type are built from; you can look but not yet change them. Changes lists every screen that looks different from the last time you approved it, at its normal and smallest size, and says what changed in words ("the button “Add” now says “Add it to the list”", "the window is now 41 by 17 cells, was 33 by 17"); Approve keeps the new look as the one to compare against. `cargo run -p todo -- --changes` says the same without a window, and `--approve` approves everything as it is. Pictures of before and after come later. `--render <folder>` also writes a page, `index.html`, with every state, light and dark, normal and smallest, and what changed under each; add `--references <folder>` to pin your own pictures (a mockup, a screenshot of another app) beside the state they are named after, such as `Empty, the mockup.png`. `cargo run -p specimen` opens Specimen on its own, on Components, and `cargo run -p specimen -- --render <folder>` draws all of its pages into pictures.

`cargo run -p todo -- --render <folder>` draws every named state of the app, light and dark, at its normal size and at the smallest window it allows, into pictures in that folder. The smallest window is worked out from the layout itself, so nothing is ever cut off by making the window small.

`cargo run -p scope` opens Scope. It lists the Graticule apps running on this computer; attach to one and Scope shows, live, how long each of its pictures took and what it spent the time on, whether the slowest one in a hundred stays inside the millisecond, how long the app took to start, and why each picture was drawn at all (a key, the pointer moving, a background job finishing). An app can only be reached from the same computer, and sends nothing until Scope asks. Boxes shows every box on the app's screen, inside the one it sits in, with the line of code that made it and why it is the size it is ("40 columns, as wide as what it shows"); two switches there draw the grid and the outline of every box over the app itself. Commands shows everything the app can do right now, with its keys, and why the rest can't run. Facts shows what the app knows, as a tree, and "Change …" sets a yes or no, a number or some words in the running app, as one step its undo takes back; Effects and jobs shows what it asked the computer for lately (files saved, links opened, work in the background), how long each took and whether it finished. Taste lists the boxes on the app's screen that break one of Assay's laws, and can mark each on the app in red. Assay now also checks that every control can be reached with the mouse, that no two items in a list read the same to someone listening, and that every color of text stays readable for people with each common kind of color blindness. When a new version of an app changes how its facts are kept, it carries what the old version saved forward instead of starting over; approving in Specimen keeps a copy of every named state's facts, and Assay checks that each copy, from every version since, still opens. Every app also answers `--ledger`: `todo --ledger` lists everything done in it, numbered, with when; `--ledger replay 12` shows what the app knew after the twelfth change; `--ledger verify` checks that replaying everything gives what was saved; `--ledger compare` shows how two copies differ, and `--ledger export` writes the whole log as text. If an app ever stops without closing, the next launch says so, and `--ledger stopped` plays back what was done in that session to see whether it fails again and at which step. It says how big each app's program is, too: about 21 MB today, 6 of them the fonts, against a proposed 10. Rewind lists every step of the app's undo history; choosing one takes the app back, or forward, to just after it, and the app's own Undo and Redo work from there.

`cargo run --release -p todo -- --assay` runs Assay over the to-do app, and the same works for every app. Assay plays the app like a careless, tireless tester: from each named state it presses keys, types, clicks whatever is on screen and runs commands by name, about four thousand steps in all, always the same ones so a result can be repeated. It checks that nothing crashes, that undo puts things back and redo puts them forward again, that a button which looks usable does something, that the app's private commands can't be reached, that what is saved opens again, and that every command can be reached at all. It looks at every state at its normal and smallest size for anything sticking out of its box, and checks that every text color is readable on the background. It times every picture and judges the slowest one in a hundred against the millisecond. When something fails, it cuts the steps down to the fewest that still show it and prints them in words ("click the button “Clear finished”"). Its first run found four real bugs in Graticule itself, now fixed: one made a long list with everything chosen slow, and two made undo wrong in Specimen.

How everything looks can be changed while an app runs, from the palette: "Use the dark appearance", "Use the light appearance" and "Follow the system's appearance", "Use the next theme" (the colors: Graticule's own, or Contrast, pure black and white) and "Use the next style" (how things are drawn: Graticule's own, or Flat, with thinner lines, no shadows and ticks in ticked boxes). The choice holds for every Graticule app and is remembered. Themes and styles are small text files; your own go in the looks folder (on Windows, `AppData\Roaming\Graticule\looks`). Every running app changes the moment one of them is saved. Specimen's Style place changes them by command: choose an ink, then make it lighter or darker, give it more or less color or turn its hue, in the light or the dark appearance, and deepen the shadow or change the lines and the check mark; everything in Specimen follows at once, each step can be undone, a step that would make text hard to read can't be taken and says why, and each ink says on how many of the app's screens it is drawn. "Save the theme and the style" writes them for every app. A theme whose text would be hard to read on its background is refused, with the color and how far it falls short.

Text on a page can be chosen with the mouse, across paragraphs and values, and copied with the usual copy keys or "Copy the chosen text" in the palette; Escape lets it go. Typing Chinese, Japanese or Korean through the system's input method shows the characters being composed, underlined, in the field, with the system's candidate list beside them. On a Mac, a right click on a row opens a menu of that row's commands, the same ones the bar shows, and a right click elsewhere offers the page's own; this hasn't been tried on a Mac yet. On Windows and Linux Graticule draws the same menu itself, a box with a hard shadow hanging from where you clicked: the arrow keys move through it, Return runs an entry, and Escape or a click elsewhere closes it.

Values look the same in every app, so you can tell what something is before reading it: a count with its thousands grouped (1,284), a date, a version in a dotted box, a state such as OFFLINE filled with its color, a product code such as DK-01 in a heavy box, a piece of code on a gray ground, a mode underlined, and an error in red. The boxed ones only say what something is; clicking them does nothing. Specimen shows them all on its Values page. Every date in every app is written one way, chosen in the palette: "Write dates as the day and time" (2026-06-01 10:00) or "Write dates as how long ago" (5 min ago, yesterday, 3 weeks ago). The choice holds for every app, beside the look. Dates written as how long ago keep themselves current: the window wakes once, at the moment one of them would read differently, and otherwise stays asleep.

Apps can show pictures: icons and small drawings, made as SVG files in any drawing program and turned into part of the app when it is built, so they cost nothing to load. Graticule comes with 42 icons for everyday things (add, close, search, folder, undo, warning and so on), which Specimen shows on its Picture page. A picture is drawn in the theme's inks, so it turns light on dark with everything else, and it always has a name that screen readers say. `cargo run -p engraver -- FOLDER` says what it would make of a folder of drawings, and refuses, with the reason, a drawing without a name or in a color that isn't one of the theme's.

`cargo run -p bindery -- new apps/hello` starts a new app: a window with a counter, two commands and one named state, ready to change, which already passes Assay and opens in Specimen. `cargo run -p bindery -- dev apps/hello` runs it and watches the code: every time a file is saved it builds the app again, and if the build works, the window closes and reopens with the new version in the same place, at the same size, with the same things in it. If the build fails, the errors show in the terminal and the app you have keeps running.

Every word an app shows can be translated. The words are written in English in the code; `cargo run -p bindery -- messages apps/todo` gathers them all into one file, `locales/en.ftl`, for a translator to copy and translate, and says for each translation what it still lacks and which of its words no longer appear anywhere, after a label was reworded. Translations use Fluent, so a language can say "1 item" and "4 items" its own way. An app opens in the computer's language when it has a translation for it, or in English; `--language de` asks for one. The to-do app speaks German. Graticule's own words, like Undo and the reasons something can't be done, are still English only.

Chinese, Japanese and Korean text needs fonts too large to keep in the repository. `cargo run -p bindery -- fonts` fetches them once for every Graticule app on the computer, and checks each against the fingerprint written in the repository, so a changed or broken file is never used. Until they are fetched, those languages are shown in the system's own fonts.

`cargo run -p bindery -- install apps/todo` builds the to-do app properly and installs it like any other program on the computer; `bindery update` later brings it up to date from its source and builds it again. After an update the app says so once at the bottom of its window, and "Show what's new" in the palette lists what changed. Nothing pops up, and Bindery looks for new versions only when asked.

Some of what an app shows changes on its own: prices from a market, the level of a microphone, a download's progress. Such a value is written by its own source as often as it likes, and the window wakes to show it at most once per picture, never more. Other values are worked out from the app's facts, a chart from thousands of prices or a count over a long list. They are worked out in the background, only when what they come from has changed, so the window never waits for them; until the new one is ready the app shows the last one, and the status line says "Working out …" with its name.
An app can also run work of its own in the background, such as a feed that keeps prices current or a search through many files. Every such job shows by its name in the status line while it runs, and if one stops without finishing, the message line says so.
Doing something to thousands of chosen items at once, or undoing a big change, happens a little at a time, between pictures, with how far it has got in the status line, so the window never stops answering; it is still one step to undo.
After an undo, or when something finishes in the background and changes the list, the rows that changed carry a small blue bar at their right edge until you next press a key or click, so you can see what moved without watching for it.

The first wave of further components is in Specimen, each on its own page: headings, separators, the keys of a command drawn from the keymap, progress and level bars, placeholders for content still on its way, tags, a person's initials, boxed messages marked with an icon in their color, and cards that box a group under a title. Then the controls: buttons that stay pressed in while something is on, buttons joined into one, buttons with a picture instead of words, switches for settings, radio buttons, groups of controls under a heading, and labels above fields with a line of help below that a screen reader reads too. Last, the ways of moving around: tabs over the pages of a panel, the places of an app along the top, page numbers, sections that open in place, a trail of where you are that shortens in the middle when it is long, and a row of actions that puts what doesn't fit into a "More…" menu. Every list now marks its top or bottom edge with a rule when there is more beyond it. Moving between tabs, places and pages can be undone like any change.

Fields now come in four shapes: one line, a search field with a magnifying glass that Escape empties, a text area of several lines that wraps and grows as you type, and text that reads as text until you click it and then becomes a field, for renaming things where they are.

Numbers have fields of their own. You can type a sum such as 12*4+3 and the field works it out when you press Return or move on; the arrows step it by one, and Escape takes back what you typed. A slider sets a number by dragging a handle along a track, with the number written after it. A code field shows one box per character, for the six digits a sign-in sends. A choice is a button that steps through its options each time you press it. A file field takes a path you type or one you pick in the system's own file window. A tag field shows a row of words, each with a cross that removes it, and a field to add another with Return. A range slider has two handles on one track, for a span such as opening hours.

Some choices now open. A select opens its options right under it, in the page, and closes when you pick one; a multi-select lets you tick several. A combo box is a field that lists matching suggestions under it as you type, which you can take with the arrows and Return or a click. A menu button opens the commands it holds as a small menu, each with its keys, and with the reason when one can't run. A popover opens a few controls under a button, such as a field to rename something. A confirm row is a button that asks first: pressing it puts the question in its place, with a button to go ahead and one to cancel. That is how Graticule asks before something that can't be undone, instead of a dialog over the page. A side panel of details beside the page is just a switch and a column, so it needs no component of its own. Opening or closing any of these is never an undo step, and Escape or a click elsewhere closes them.

Days and times have components now. A calendar shows a month with the chosen day filled and today underlined; the arrows move between days and the buttons beside the month turn it. A date field takes a date or plain words, such as tomorrow, next tue, in 3 days or jun 3, and a time field takes 15:30, 3pm or noon; in both, the arrows step the value. A date picker is a date field with a button that opens a calendar beside it. A time zone field suggests the world's zones as you type their names.

Colors have components too. A color is kept as lightness, chroma and hue, the way the eye sees it, so that a lighter version of a color looks just as vivid. A color field shows a small swatch and takes a hex code such as #3366cc or an OKLCH value; sliders set each part and show along their track the colors they would give; an area sets lightness and chroma together by dragging or the arrows. A color picker is a color field with a button that opens the area and a hue slider.

Apps can now draw. A canvas is a box with a space of its own, for charts and small diagrams: lines, filled shapes, dots and words in the theme's inks, drawn again only when what they show changes, and away from the thread that answers the keyboard. A dot or a bar on a canvas can do something when it is clicked, or reached with the arrows. Raster images, such as photographs and scans, sit in boxes of cells and keep their shape. For anything else an app can paint a canvas with its own GPU code, which still follows the theme. In Specimen each component's live example now sits under its first sentence, so the pictures of every page show it.

Tables have arrived. A table is a list with columns: a row of heads, then a row for each item, words on the left of their column and numbers on the right. Pressing a head sorts the table by that column, then the other way, then back. The sorting happens away from the thread that answers the keyboard, so a table of millions of rows sorts without the window stalling; until it is done the rows keep their old order. Dragging the gap after a head makes that column wider or narrower, and a narrow window leaves out the columns that don't fit, from the right.

Trees came next: folders inside folders, an outline, places inside places. A branch opens and closes with a click on its arrow, or with the right and left arrow keys, which also move into a branch and back up out of it, the way trees work everywhere else on the computer.

Then split panes: a list on the left and the thing chosen in it on the right, with a line between them that can be dragged to give one side more room. The line can also be reached with Tab and moved with the arrow keys. How wide the user made each side is remembered with the window, like where a list was scrolled, so it isn't something undo takes back. In a window too narrow for both, the panes sit one above the other. The panes can be rearranged too: moved left or right, closed, and opened again, all from the palette. Save the layout writes the arrangement to a small text file next to the keymap, and Use the saved layout puts it back, so a layout you like can be kept or copied to another computer.

The picker is the palette's search for an app's own things: type a few letters of a file's or a place's name and the ones that have those letters, in that order, come up, the best first, with the letters you typed underlined. Matches at the start of words, or letters that sit together, count for more, so "lo" puts London before Lisbon. The arrow keys move between them and Return opens one. The searching happens away from the thread that answers the keyboard, so a picker over millions of things keeps up with the typing.

A typed filter narrows a table by what its records hold: `people>1000000 country:spain` keeps the cities of more than a million people in Spain. It knows the fields from the app's own description of a record, so an app gets one without saying anything more, and it offers the field names as they are typed. When a query can't be read, it says why under the field, such as a field the records don't have, and keeps showing every row until it can.

A table can also be made from the records alone: one column for each thing a record holds, headed by its name, sorted by pressing a head like any table. It suits places where the data is the point, such as a log or an inspector, and a new field in the record is a new column without anything else changing.

The time axis is the start of a sequencer or a video editor: a ruler across the top, counted in plain numbers, in minutes and seconds, or in bars and beats, and below it a row for each track with what happens when drawn along it. A click on the ruler moves the playhead, which lands on the nearest mark; the arrow keys move it mark by mark. Holding Ctrl (Cmd on a Mac) while turning the wheel zooms in and out around the pointer, and Shift with the wheel scrolls through time. The marks always land on whole cells of the grid, however far in or out.

Charts draw numbers as lines, bars or candles, the kind traders read, with a scale up the left and along the bottom. The app says how many rows tall a chart is, and Graticule picks round numbers for the scale so each one sits in the middle of a row. A table can carry a sparkline in a cell: a tiny chart of a row's trend, where the shape matters more than the values. Pointing at a chart to read a value off it isn't done yet.

A node graph shows boxes joined by wires, such as the states a post moves through. The app only says which boxes lead to which; Graticule sets them out from left to right so the wires run forward and cross as little as it can, and a loop is drawn running back. In a window too narrow for it, the boxes are listed one under another instead.

A diff view shows what changed between two versions of a text: lines taken out in red, lines put in in green, and inside a line that changed, the words that changed marked more strongly. Long stretches that stayed the same fold into one line saying how many, so the changes stand out. However long the text, only the lines on screen are drawn.

Apps can take files dragged in from elsewhere on the computer: while they hover over the window, the status line says what dropping them will do ("Import a file"), or why it can't. A list can let you drag its rows into your own order: a line shows where the row will land, the status line says the move, Escape puts it back, and the move undoes in one step. Dragging a file out of a Graticule app onto the desktop isn't possible yet, because the windowing library underneath can't start that kind of drag.

`cargo run -p galley-face` opens Galley, Graticule's text editor: a file to open and save, the text, and under it a field to find a word and one to replace it with. The editor takes text of any length, since it only ever reads the lines on screen, and as many cursors as you make: "Select every match" puts a cursor on every place the word appears, and what you type then goes in at all of them. "Add a cursor above" and "Add a cursor below" put another cursor on the next line up or down, and "Add the next match" selects the next place the selected words appear; the keymap file gives them keys. While there is something in the find field, every place it appears is underlined, and "Find the next" and "Find the previous" (Ctrl-G and Ctrl-Shift-G, Cmd on a Mac) select each in turn. The keys are your system's own, undo takes back a word at a time and puts the cursors back where they were, and the editor scrolls to follow you. Long lines wrap at the window's width, and the up and down arrows move through the wrapped rows as they show, not by whole lines. Input methods for Chinese, Japanese or Korean work in the editor as in any field: what is being composed shows underlined at the cursor until it is chosen. Replacing every match happens in the background, named in the status line while it runs, so even a very long file never makes the window wait; if you type while it runs, it says so and replaces nothing, and you can run it again.

Galley can also work like Vi, with keys that move and act instead of typing until you ask to type. It starts as a plain editor; "Edit the keys" opens its keys file, where the modal keys are written out with a # in front of each line, and taking the #s away switches them on at once: h, j, k and l move, w and b go by words, i starts typing and Escape stops, v chooses, and d, c or y followed by a movement deletes, changes or copies over it. The bar always says which mode is on.

Galley folds too: "Fold the block" hides the lines indented under the one the cursor is on, leaving that line with a faint count of how many are hidden, and "Unfold" or "Unfold everything" brings them back. A fold opens by itself when you edit inside it or a search lands there. A file whose name ends in `.rs` shows its code in colour: keywords and type names, text in quotes and comments each in their own ink. Apps can do the same for any language, and underline misspelt words, by plugging in a parser or a spellchecker; which colours and which spellcheckers come with Graticule is a question for the owner.

Every app also has a command line, for people who would rather type a command's name than look for it: "Type a command by its name" in the palette (or `:` in Galley's modal keys) opens a line at the bottom where `fold` runs Fold the block, Tab finishes a half-typed name, and whatever comes after the name answers the command's question, so `write hello` writes "hello" in one go.

Galley holds several texts at once, each in a buffer: "New buffer" starts another, "Next buffer" and "Previous buffer" go round them, and the line above the text says which one you are in. "Split" shows a second buffer beside the first, or under it in a narrow window, "Swap the panes" trades them and "Close the split" goes back to one.

Plotter, the whiteboard's engine, has its core: a board of boxes, ellipses, text, freehand strokes and arrows, where an arrow tied to a box stays on it however the box moves or grows, and one undo takes back both. Shapes snap to each other's edges and centres while they move. A board exports to an SVG picture that any browser shows, and the picture carries the board inside it, so opening the picture again gives back the board exactly.

`cargo run -p plotter-face` opens that whiteboard. The buttons along the top pick what a drag does: choose and move shapes, or draw rectangles, ellipses, arrows or freehand lines; after drawing a shape it goes back to choosing. A click chooses a shape and Shift with a click adds more; a drag on empty board chooses everything inside the box it draws; a drag on a chosen shape moves it, lining it up with the edges and middles of the others and showing the line it lined up with, or spacing it evenly with the shapes beside it and showing the equal gaps; a drag on a corner of the chosen shapes resizes them, several or a group stretching together, and a drag on the middle of a side moves only that side; the dragged edge lines up with the edges of shapes in line with it. "Write…" asks for some words in the palette and puts them on the board, inside the chosen shape if there is one, or gives the chosen text its new words. An arrow drawn from one shape to another holds on to both. The wheel moves around the board and, with Ctrl (Cmd on a Mac), zooms in and out around the pointer; "Show everything" brings the whole board into view. The ink chosen at the top colours the chosen shapes and every shape drawn after; "Lock" keeps the chosen shapes from being moved, resized, rewritten or recoloured until "Unlock". The Frame button draws a named box that takes in whatever is inside it; shapes dropped in it join it and move with it, and what reaches past its edge is hidden. "Write…" renames a chosen frame. "Write on the board" opens a box right over the chosen text or frame name to type into; Return keeps the new words and "Drop the words" leaves them as they were. "Read only" keeps the board as it is: shapes can still be chosen, copied, saved and exported and the view moves, but nothing changes, not even by undo, until "Allow editing". A board can have several pages: the menu beside the ink shows the page's name, goes to the others, and adds, renames or removes pages; removing a page removes what is on it, and a board always keeps one. "Group" holds the chosen shapes together, so a click chooses them all and they move, copy and go as one; "Ungroup" lets them go again. "Copy" and "Paste" copy the chosen shapes, arrows still attached, within a board or between boards, and what is copied is an SVG picture other programs can paste too; pasting plain words puts them on the board as text. A board saved as SVG and dropped on the window, or chosen with "Import…", is added on top of what is there; a PNG or JPEG picture is placed in view the same way, and saves, copies and exports with the board. Beside the board, a map shows the whole of it small, with a box round the part in view; a click on the map moves the view there. Escape drops a drag halfway. With the keyboard, Tab reaches the board, the arrows go from shape to shape with a screen reader saying what each is, and Return chooses one. The arrow keys move the chosen shapes a little at a time, as the keymap file says. Freehand lines are drawn the way a pen draws, thinner where the hand moved fast. The board saves as an SVG file, which any browser shows and the whiteboard opens again, and "Export a picture" writes a PNG of the whole board, words included, beside it.

## How speed is measured

A screen refreshes 60 to 1000 times a second; at 1000, there is one millisecond per picture. Graticule's goal is to finish its work for an ordinary interaction in a tenth of that, and to do nothing at all when nothing is happening, which is what saves battery. Times are measured automatically and judged by the slowest frames, not the average, because the slow ones are the ones you notice.

## How you review

- **Pictures**: Specimen's Changes page, before and after, with the change described in words.
- **Numbers**: the budgets, which say plainly when something got slower.
- **Sentences**: this guide, and `docs/api.md`, the code we want app makers to write. If you can follow it, it's right.
